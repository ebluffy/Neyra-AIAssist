# Развёртывание identity ядра

Пакет меняет зависимости и контракт signer; одного `git pull` недостаточно.
Перед запуском новой версии установить `pip install -r server/requirements.txt` в используемый ядром venv (PyJWT==2.15.1). CI-установки закреплены на той же версии.

Согласованно передать в окружение ядра и сайта отдельный стойкий `NEYRA_IDENTITY_JWT_SECRET` (не менее 32 байт UTF-8) и issuer. Ядро читает ожидаемое значение из `NEYRA_IDENTITY_JWT_ISSUER`, сайт должен добавлять точно такое `iss` в JWT. Ни секрет, ни issuer не имеют неявного значения по умолчанию. Не использовать ключ service API как signing secret.
Сайт, который пока не отправляет `iss`, с новой проверкой получит 401: сначала подготовить signer и окружение обоих сервисов, затем включать интеграцию. Настоящие значения хранятся вне репозитория; не вставлять их в команды, логи, отчёты или PR.

JWT: HS256, обязательные iss/sub/role/name/iat/exp, TTL ≤60 секунд, часы сервисов синхронизированы, leeway 0. Подписанный user не имеет доступа к общим ops-ручкам памяти: разрешены только scoped search/chat-recall и своя карточка. /v1/web/me сообщает limits:null до отдельной реализации лимитов.

Перед допуском трафика проверить зависимости, отрицательный запрос с неверным issuer (401), /v1/web/me (свой текущий person_id, в том числе после merge), невозможность прочитать чужую память (403) и готовность WS denial/trace через выбранный ASGI server и reverse proxy. Рабочий API key остаётся обязательным и ограничивает доступ независимо от JWT.

Эти инструкции описывают подготовку владельцем деплоя. Сервисы, конфигурация и данные не изменяются самим патчем.
