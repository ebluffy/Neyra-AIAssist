# Гайд конечного пользователя

- Запустите ядро: `python server/main.py` (или из cwd `server/`: `python main.py`).
- Откройте веб-дашборд: `http://127.0.0.1:8787/` (SPA на React + Vite + Tailwind).
- **Первый визит:** задайте **ключ доступа к дашборду** (не менее 8 символов; удобно сгенерировать hex-32). Дальше — вход тем же ключом. Подробнее: [web-ui](../architecture/web-ui.md).
- Для чата используйте плагин Discord (`server/modules/discord`) или HTTP `POST /v1/chat`.
- Состояние ядра, память и плагины — в разделе **Dashboard**; webhooks и токен API — в **Webhooks** / **Settings**.
- После входа дашборд получает session-токен и ходит в `/v1` с ним (роль admin). Отдельный `API_TOKEN` в `.env` / **Settings** — для Discord, MCP и скриптов.

Публичный API (если настроен): `https://neyra.owyx.site/api/v1`; streaming-чат по WebSocket: `wss://neyra.owyx.site/api/v1/ws/chat` — см. [api-reverse-proxy](../ops/api-reverse-proxy.md).

## Управление компьютером в Tauri-клиенте

На Windows клиент использует UI Automation, на macOS — Accessibility. Включите доступ к ПК и разрешения на снимки экрана и ввод в настройках клиента. На macOS также разрешите Neyra доступ в **Системные настройки → Конфиденциальность и безопасность → Универсальный доступ**. На Windows защищённые окна и приложения с более высокими привилегиями могут быть недоступны.

Host bridge предоставляет четыре инструмента:

- `client.computer_snapshot {}` возвращает JSON-дерево доступности активного окна с идентификаторами `ref`. Используется разрешение на снимки экрана; без автоматического разрешения (`screen_auto`) нужна карточка подтверждения.
- `client.computer_click {"ref":"…"}` выполняет нативное действие элемента.
- `client.computer_type {"ref":"…","text":"…"}` **заменяет содержимое** редактируемого поля указанным текстом.
- `client.computer_press {"keys":["Ctrl","a"]}` нажимает сочетание клавиш в активном окне. На macOS используйте `Meta` для Command.

Три изменяющих инструмента требуют разрешения на ввод и отдельного подтверждения, как существующие действия host bridge. «Стоп» отменяет ожидающие действия; уже выполненное действие не откатывается.

`ref` относится к последнему снимку активного окна и действует до 120 секунд. Новый снимок, попытка изменения, «Стоп», отключение bridge или изменение разрешений делают прежние ссылки недействительными. После каждой попытки изменения получите новый снимок. Переключение окна до выполнения действия также приводит к отказу. Значения текстовых полей в дерево не включаются; это не исключает чувствительные сведения в названиях других элементов.

Коды ошибок: `stale_ref`, `not_found`, `permission_denied`, `unsupported_platform`, `timeout`, `cancelled`, `invalid_arguments`, `action_failed`. При `stale_ref` нужен новый снимок. После `timeout` или `action_failed` сначала проверьте состояние новым снимком: изменение могло уже произойти, поэтому автоматически повторять его нельзя. Сообщения ошибок не содержат введённого текста.

Поддержка зависит от дерева доступности приложения: если оно не предоставляет нужное нативное действие, инструмент возвращает ошибку. Подмены через координаты или OCR нет. На Linux новые инструменты возвращают `unsupported_platform`; существующее управление Linux остаётся прежним.
