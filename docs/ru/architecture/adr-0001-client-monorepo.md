# ADR-0001: клиентский монорепо и общий UI-кит

- **Статус:** принято, 11.11.2026
- **Контекст:** реформа веба (§6) и десктоп-клиент (§7) развиваются одновременно
- **Решение принимает:** владелец по предложению ведущего разработчика

## Контекст

Сейчас есть два React-приложения с разными UI-стеками:

| | `client/` (десктоп) | `server/dashboard` (веб) |
|---|---|---|
| Стили | `styles.css` + `theme.ts` | Tailwind + `tokens.css` |
| Компоненты | самописные | Radix/shadcn, 22 файла примитивов |
| Роутер | нет | `createBrowserRouter` (react-router 7) |
| Данные | ручные fetch/IPC | TanStack Query + Virtual |
| Формы | руками | react-hook-form + zod |
| Тесты | 233 Vitest (на 11.11.2026) | Vitest + Playwright e2e |
| 3D | three + three-vrm | — |

Если оставить два UI, после реформы снова получится два дизайн-языка — та же проблема, ради которой затевается реформа.

## Решение

1. **Монорепо с общим китом и двумя тонкими приложениями:**
   - `packages/ui` — токены, тема, Radix/shadcn-примитивы;
   - `packages/contracts` — zod-схемы HTTP/WSS и desktop-моста;
   - `apps/web` — нынешний дашборд и веб-клиент;
   - `apps/desktop` — фронт Tauri на том же ките.
2. **Rust не трогаем.** `client/src-tauri` (cpal, PTT-хоткеи, keyring, updater) и `client/overlay.html` остаётся, IPC-контракт тот же. Аппаратная приёмка (keyring, трей, хоткеи, микрофон) делается один раз и не зависит от UI.
3. **Оверлей и окно персонажа — отдельные webview** со своим минимальным бандлом (three-vrm). В общий SPA их не тащим.
4. **Роутер:** `createBrowserRouter` для веба и hash/memory-вариант для Tauri, иначе под `tauri://` маршруты поедут.
5. **Адаптер платформы:** PTT, keyring, устройства ввода и screen capture в браузере недоступны. Это показывается как «только в приложении», а не прячется.
6. **Раскладка:** чат — full-bleed, ops-экраны — плотные «список + деталь».

## Последствия

- Чат-поверхность — около 12 компонентов (`ChatView`, `Composer`, `LiveVoice`, `VoiceOrb`, `HistoryPanel`, панели настроек) и 3 экрана; их нужно перенести на Radix-кит вместе с 233 UI-тестами (на 11.11.2026). Это самая объёмная часть эпика.
- Порядок работ: монорепо + `packages/ui` + `packages/contracts` + пустой каркас Tauri-фронта → перенос ops-экранов → перенос чата.
- Аппаратную приёмку гонять уже на новом UI, чтобы не тестировать дважды.
- Старый `client/` UI и `server/dashboard` не удаляются до паритета; после переноса — удалить.

## Рассмотренные альтернативы

- **Оставить два UI.** Отклонено: два дизайн-языка и двойная работа.
- **Один SPA вместе с оверлеем и персонажем.** Отклонено: разная нагрузка и отдельные окна.
- **Переписать Rust под новый UI.** Отклонено: ломает уже принятую аппаратную часть и IPC.
