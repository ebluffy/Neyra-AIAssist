# История версий Neyra

Для новых поставок используется `MAJOR.MINOR.PATCH`: несовместимое изменение
контракта, новая совместимая функция, совместимое исправление. Пока проект
разрабатывается, major остаётся `0`. Версия Control API и версии отдельных
пакетов ведутся отдельно; этот журнал их не меняет.

Запись со статусом «в разработке» не означает опубликованный релиз, merge или
деплой. После выпуска фиксируются дата и tag/commit. Невыпущенные изменения
добавляются в текущую запись; новую версию заводим при следующей поставке.
Открытые задачи, баги и критерии live-приёмки находятся в [PLAN.md](PLAN.md).
Общие руководства сохранены в `en/` и `ru/`.

## 0.1.0 (в разработке)

Наблюдаемость LLM: сорванный ход сохраняет `model_trace` в `chat_log` (`role=model_trace`, пустой текст, вне истории диалога) со `status` и `error_class`. У хода отдельно `queue_wait_ms`. У вызова, где видно, есть время до заголовков, первого SSE-события, рассуждения и первой текстовой дельты, терминальное событие, причина `incomplete`, слой повтора и счётчик повторов SDK. HTTP Responses пишется в `system.log` (`neyra.llm.http`, INFO) без тела и секретов. `response.incomplete` с `max_output_tokens` после текста завершает ход усечённым ответом. Бюджет Responses — `reply_max_tokens` плюс `output_token_headroom` (по умолчанию 2048). Если этот бюджет больше видимого лимита, стрим останавливается на той же обрезке, что и сохранённый ответ, ход помечается `truncated` / `visible_cap`, а цепочка Responses с невидимым хвостом не продолжается. Для chat-completions обрезка по символам не включается. Повторы первого токена делят `turn_timeout_seconds` (по умолчанию `timeout_seconds`), а рассуждение считается признаком жизни стрима.

### Добавлено

- Сохраняемые Mood & Relations по person_id: ограниченные изменения, decay,
  reset с backup, SQLite migrations 6/7, API и dashboard.
- 17 переключателей необязательных подсистем, включая Responses для talk и
  платный прогрев persona; строгие boolean, отдельные требования к рестарту.
- Цепочки Responses с общим неизменным seed, независимыми беседами и
  ненаследуемым приватным контекстом хода. Общий Discord-канал отделён от DM
  и личной памяти; заложен private scope будущего приложения.
- Отдельная вкладка объединений людей: поиск, страницы, имена, причины,
  история и отмена с подтверждением.

### Исправлено

- Persona поступает прямо в talk; brain получает scoped историю, факты и
  состояние. Готовый текст talk не переписывается brain. Brain-native vision
  обходится без отдельного caption-вызова тем же клиентом.
- Повторы после empty/overflow сохраняют persona и нужные факты, не повторяют
  инструменты и не раскрывают private reasoning. После публичного текста
  поток не перезапускается; до публикации скрытый reasoning не блокирует retry.
- Warmup не содержит фиктивного состояния; state policy/data передаются
  только текущему вызову. Ошибки Discord/REST/WS имеют безопасный публичный текст.
- Discord отправляет готовый ответ без чернового курсора, typing и edit.
- Запись факта не создаёт человека по неизвестному нику/ID; account ID выбирает
  каноническую карточку, неоднозначные имена отклоняются. Старый кэш/reflection
  не воскрешают merge source и не перезаписывают актуальные aliases/аватар.

### Документация
