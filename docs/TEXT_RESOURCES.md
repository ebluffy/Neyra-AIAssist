# Серверные ресурсы текстов — первая поставка §14

`server/resources/` содержит только статические строки. Пользовательские
диалоги, память, секреты, числовые лимиты, API-коды и права доступа остаются
в своих слоях. Persona и appearance — существующие файлы `server/prompts/`,
не переводы и не инструкции brain.

| Каталог | Назначение | Состояние |
| --- | --- | --- |
| `prompts/en.json` | 70 английских блоков system policy и вспомогательных инструкций | Подключены к серверным callers |
| `messages/ru.json` | Пользовательские fallback-сообщения | Brain unavailable и empty reply |
| `messages/en.json` | Английские сообщения и fallback | Те же два ключа |

Полная локализация API, Discord и dashboard, остальные data wrappers и tool
descriptions ещё не перенесены. Переключателя языка приложения эта поставка
не добавляет. Язык сообщений не меняет язык служебной политики или ответа LLM.

## Использование

`core.text_resources.prompt_text("talk.speaker_label", username=label)`
загружает только английский prompt. Значения подставляются как данные один раз:
фигурные скобки внутри label не становятся новым шаблоном.

`message_text("brain.unavailable", locale="ru")` выбирает перевод. Русский —
default существующих callers; отсутствующий перевод и неизвестная locale
используют английский. Неизвестный ключ — ошибка, а не вывод ключа пользователю.

Шаблоны используют `{parameter}`. Для буквальных скобок (например JSON coder)
нужны `{{` / `}}`. Позиционные поля, attribute/index access, conversions и
format specifications запрещены. Пропущенные и лишние параметры отклоняются;
ошибки не включают подставленные значения. Переводы должны иметь тот же набор
параметров, что английский исходник.

Пути фиксированы относительно server package, а не cwd; пользовательский путь
не принимается. Каталоги кешируются до рестарта процесса. Изменение JSON требует
рестарта; прежнее чтение persona-файлов не меняется. Штатные каталоги обязательны:
отсутствие файла, malformed JSON, дубликаты ключей или неверные типы — явная ошибка.
В Docker JSON попадает через существующий `COPY . /app/`; `.md` в image не нужен.

## Проверки и неизменность поведения

- `python server/scripts/verify_text_resources.py` проверяет каталоги без
  моделей, токенов и runtime memory; шаг включён в CI LLM/memory.
- `tests/fixtures/prompt_contracts.json` зафиксирован из смерженного #27 до
  переноса: фиксированное время, только синтетические persona/данные. Пять
  режимов, micro-plan, vision/previous image, lyrics и brain context должны
  совпадать побайтно с этими снимками.
- Тесты проверяют реальные ссылки из Python callers, параметры и отсутствие
  неиспользуемых prompt keys; отрицательные сценарии загрузчика и ru/en fallback.
- Повтор пустого ответа получает `lyrics_mode` из состояния хода в chat и
  streaming. Редактирование заголовка `talk.lyrics` и цитаты пользователя не
  меняют выбор полного/обычного retry; это проверяют пять сценариев.
- Регрессии реального pipeline сохраняют persona только в talk, human-role
  Discord/context, scope памяти, retries и model evidence. Живые модели не
  вызываются. Результаты mock/offline не доказывают качество runtime-модели.

Изменение ресурсов может изменить поведение модели так же, как правка кода:
новые тексты должны проходить review и тесты; не регенерировать golden ради
маскировки отличий. §7.5 Mood/Relations остаётся следующей отдельной задачей.

Локальная проверка первой поставки: **219 server tests**, compileall,
**14 stage/offline scripts**, validator каталога; **10 desktop/mobile E2E**
с временной SQLite и заглушками моделей. Dashboard build на Node 22 прошёл.
UI-код не менялся; новая логика загрузки проверяется также CI этого PR.
