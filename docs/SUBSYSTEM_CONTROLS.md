# Управление необязательными подсистемами

Settings → «Поведение» управляет 15 сохранёнными boolean-параметрами через
существующий admin API `/v1/config/update`. Изменения сохраняются по слоям YAML;
не требуется пересобирать LLM-клиенты. API отвергает строки, числа и null вместо
boolean до изменения конфигурации. `/v1/config/runtime` показывает реальные
значения, включая значения по умолчанию, если ключ ещё не записан.

Пустые необязательные вложенные YAML-блоки (например, `working_memory:` без
полей) сохраняют совместимость: используются значения по умолчанию. Сам флаг
должен быть boolean: `enabled: null` или строка `enabled: "true"` теперь
вызывают ошибку проверки при запуске; используйте `enabled: true`/`false`.

| Настройка | По умолчанию, если отсутствует | Когда применяется |
| --- | --- | --- |
| `memory.mood.enabled` | true | Следующий ход, независим от relations |
| `memory.relations.enabled` | true | Следующий ход, независим от mood |
| `memory.diary_after_turn` | true | Следующий ход |
| `memory.working_memory.enabled` | false | Следующий ход |
| `memory.pre_context.enabled` | false | Следующий ход |
| `memory.emotional_layer.enabled` | false | Следующие задания записи памяти |
| `memory.emotional_layer.ltm_emotion_sync` | false | Следующие задания записи памяти, требует предыдущего флага |
| `agent.de_repeat.enabled` | true | Следующий ответ; выключает дополнительный вызов talk для перефразирования |
| `memory.rag_enabled` | true | После мягкого рестарта: загрузка/поиск Chroma |
| `memory.reflection_enabled` | true | После мягкого рестарта: главный переключатель фонового планировщика |
| `memory.small_reflection_enabled` | true | После мягкого рестарта, требует планировщика |
| `memory.diary_hourly_enabled` | true | После мягкого рестарта, требует планировщика |
| `memory.ltm_auto_prune.enabled` | false | После мягкого рестарта, требует планировщика |
| `memory.ltm_auto_summarize.enabled` | false | После мягкого рестарта, требует планировщика |
| `mcp_client.enabled` | false | После мягкого рестарта: существующие спецификации MCP; сохраняется в modules.yaml |

Существующие YAML-значения имеют приоритет над указанными defaults; при обновлении
не включается то, что уже было явно выключено. Для MCP и фоновых расписаний UI
показывает необходимость рестарта; сохранение не выполняет рестарт самостоятельно.
Уже начатые задания diary/WM/эмоциональных заметок могут закончиться.

Отключение mood/relations останавливает обновление выключенной части и её
передачу в talk. Данные не удаляются, но decay продолжает учитывать прошедшее
время. Переключение инвалидирует незавершённые affect-записи, чтобы выключение
и быстрое обратное включение не применили старый ход. GET affect и Memory panel
показывают флаги и поясняют, что сохранённые значения не активны. Сброс остаётся
отдельным подтверждаемым действием с бэкапом.

Рабочая память, предварительная сводка и дневник — разные функции. Отключение
одной не очищает SQLite/историю и не отключает остальные. Отключённый планировщик
не отменяет ручные операции памяти и дневник после каждого хода.

## Уже существующие средства управления

- Модули/Discord/music — enable/disable на экране «Модули», без дублирующих флагов.
- Fast path — Settings → «Система», действует со следующего хода без рестарта.
- Vision, brain-native vision и запоминание изображения — Settings → «Зрение»;
  существующий механизм пересборки LLM-клиентов при изменении `llm.*`.
- Монитор здоровья и его период — Settings → «Система», нужен мягкий рестарт.
- `memory.rag_write_mode` — Settings → «Память»: off/digest/important_only/legacy_dialog.
  Теперь изменяет также действующий MemoryHub без рестарта; поиск RAG управляется
  отдельным переключателем. Уровень логов также применяется сразу.

Авторизация, role checks, ID/scope памяти, нормализация Discord и защита приватных
данных остаются обязательными условиями работы, без переключателей обхода в UI.
Клиент, Agent loop и двухботовый голос в эту поставку не входят.

Проверки: сохранение/перезагрузка каждого флага, строгие boolean, отсутствие LLM
rebind, фактическое отключение mood/relations/diary/rewrite, отмена и ошибки UI,
обе темы, мобильная ширина. Live-проверки MCP и новых расписаний на рабочем сервере
выполняет пользователь после отдельной команды на деплой/рестарт.
