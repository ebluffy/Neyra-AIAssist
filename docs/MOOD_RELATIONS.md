# Mood & Relations: серверный MVP

Следующий этап после PR #28, по §7.5 PLAN. Реализация работает без нового
LLM-вызова. Оценка поведения настоящих моделей и Discord остаётся live-приёмкой.

## Контракт состояния

SQLite migration 6 добавляет `neyra_state`, `person_relations`, `affect_turns`
и служебный счётчик сбросов `affect_meta`. Migration 7 добавляет индекс TTL
ledger и таблицу `affect_mood_events` для часового бюджета авторов. Миграции добавочные; существующие
диалоги, факты, дневник и accounts сохраняются.

- Mood глобален: valence −1…1, arousal 0…1, вычисляемый label. Начало — 0/0.
- Relations принадлежат `person_id`, который выбирается по account ID.
  Handle, имя, упоминания и одинаковые display name не выбирают отношения.
  При отсутствии ID передаётся только глобальный mood.
- Affinity −1…1, trust/familiarity 0…1. Начало — 0/0.5/0.
- Это субъективные параметры реакции ассистента, а не установленные факты
  о человеке. Шкалы не отражают объективную достоверность его слов.

## Изменения и время

После успешного хода один SQLite transaction обновляет mood, отношения
активного автора и ledger обработанных `turn_id`. Ledger хранит только ID хода
и время; повтор одного ID в течение 30 дней, в том числе после рестарта, ничего не меняет.
При следующем записываемом ходе строки старше 30 дней удаляются в той же
транзакции; в состоянии простоя ledger не растёт.
Обычный чат, streaming и fast path используют один finalize. Ошибка генерации
не меняет состояние. Wipe во время генерации инвалидирует запись старого хода.

Правила версии `explicit_cues_v1` проверяют первые 12 000 символов. Приоритет:
явное признание лжи → прямое оскорбление ассистента → извинение → благодарность.
Применяется только один сигнал; иначе только familiarity +0.01.

| Сигнал | Δvalence | Δarousal | Δaffinity | Δtrust |
| --- | --- | --- | --- | --- |
| «я соврал/солгал», “I lied” | −0.04 | +0.02 | −0.02 | −0.03 |
| «ты тупая/дура/бесполезная», “you are/you’re stupid/useless” | −0.10 | +0.08 | −0.04 | 0 |
| «извини/извините/прости/простите», “sorry/I apologize” | +0.04 | −0.02 | +0.02 | 0 |
| «спасибо/благодарю», “thank you/thanks” | +0.04 | −0.01 | +0.01 | 0 |

Глобальный mood получает от одного person_id не более 0.2 суммы абсолютных
дельт по каждой оси за скользящий час. Отношение к этому автору продолжает
меняться. Для запросов без идентифицированного автора действует общий
анонимный бюджет; отключённые отношения не выключают лимит автора.
Технические события бюджета очищаются на следующем записываемом ходе после часа, reset mood не обнуляет
антиспам-бюджет.

Вежливость не повышает trust. Все изменения ограничены диапазонами в коде и
CHECK constraints SQLite. Это простой набор сигналов, а не полноценный
анализ контекста: цитаты, отрицания, ирония и другие языки требуют отдельного
развития и живой проверки. Нет штрафа за молчание или отсутствующие сообщения.

Decay вычисляется при чтении и перед записью по UTC-времени: mood к 0/0
с полупериодом 8 часов; relations к 0/0.5/0 с полупериодом 30 дней.
Поэтому первый запрос после рестарта учитывает всё время простоя без cron;
повторные чтения не ускоряют decay. Откат часов не усиливает значения.
История содержит последние 20 кодов сигналов и время, без текста диалога.
Существующий per-turn diary продолжает работать отдельно.

## Pipeline

В talk отправляется компактный HumanMessage с mood и отношением к автору,
без истории сигналов. Он сохраняется при context-overflow retry.
Английская инструкция `talk.state_policy` находится в каталоге ресурсов:
persona и границы поведения сильнее состояния; запрещены наказание,
манипуляция и отказ в полезной помощи из-за affinity. Brain не получает этот
блок или стилистические инструкции. Низкий score не меняет доступ к памяти.

## API и dashboard

- `GET /v1/memory/affect?person_id=…` — viewer+, снимок mood и выбранных
  отношений; без person_id только mood. Неизвестный person_id: 404.
- `POST /v1/memory/affect/reset` — admin, `{scope: "mood" | "relations",
  person_id?: string, confirm: "WIPE"}`. Person ID допустим только для relations;
  без него сбрасываются все отношения. Перед изменением создаётся SQLite backup с уникальным именем; существующий файл не перезаписывается. Аудит содержит scope, person_id и путь бэкапа.
- Существующий `/v1/memory/wipe` принимает новые scopes `mood`/`relations`.
  Остальные scopes сохраняют прежнее поведение. Wipe people также удаляет
  отношения. Diary/chat/facts не удаляются при сбросе mood/relations.
- Merge сохраняет отношение survivor; source сохраняется в merge snapshot.
  Undo восстанавливает source, если после merge не было сброса отношений.
  Сброс не воскрешает данные через undo. Удаление человека каскадно удаляет
  его отношения. Резервная копия включает состояние и ledger.

Memory → Обзор: настроение, выбор человека с ID, отношения, обновление,
три отдельных сброса с вводом «СБРОСИТЬ». Ошибка сохраняет диалог и возможность
повтора. Данные старого человека не показываются под новым именем.

## Проверки

Серверные тесты покрывают миграцию копии v5 и повторную миграцию, restart,
диапазоны/decay/откат часов, trust, конкуренцию/idempotency, одинаковые имена,
accounts, scopes/reset/backup/merge/undo, настоящий pipeline chat/streaming,
fast path без LLM, неуспешный ход, reset во время генерации и context retry.
Dashboard unit/E2E проверяют API-ошибки, подтверждение/отмену/повтор, запись и
повторную загрузку через настоящий временный backend, обе темы и mobile.
Результаты финальных прогонов фиксируются в PLAN; mock не закрывает live-пункты.

Использованы навыки из [agent-tool-catalog](https://github.com/ebluffy/agent-tool-catalog):
shadcn, fixing-accessibility, make-interfaces-feel-better, ui-ux-pro-max;
локально дополнительно fastapi. Основа интерфейса — dashboard/DESIGN.md:
сохранены токены, шрифты и общие компоненты. Новых UI-библиотек нет.


Финальные локальные прогоны: 279 server tests; compileall; validator 71/2/2;
14 stage/offline scripts; dashboard Node 22 lint/typecheck, 38 unit tests,
production build и 14 desktop/mobile E2E. Существующие предупреждения:
react-hooks/incompatible-library в LogViewer и размер JS bundle >500 kB.

### Проверка интерфейса

Полный просмотр новой панели, React + текущие Tailwind/CSS-токены. Другие
экраны не перерабатывались. Скриншоты desktop/mobile в обеих темах проверены.

| Область | Проверка / результат |
| --- | --- |
| Typography | Текущие Fira Sans/Code, tabular numbers; длинный ID обрезается в trigger, раскрывается в списке |
| Surfaces | Существующая card, токены обеих тем; minmax(0,1fr) предотвращает внутреннее обрезание на mobile |
| Animations | Новая анимация не добавлялась; существующие переходы компонентов сохранены |
| Icons | Новые декоративные иконки не добавлялись |
| Performance | Снимок запрашивается при выборе/refresh/reset, без polling и новых UI-зависимостей |

Найдены и исправлены: потеря фокуса после отмены диалога и обрезание содержимого
мобильной карточки. Регрессии включены в Playwright. Подтверждены loading/error/
empty, отмена/reset/retry, защита от старых ответов при смене person ID,
keyboard-открытие Select и возврат фокуса после диалога.
Были отклонены новые графики и анимации: числовые шкалы читаются без них,
а текущие токены и общие компоненты уже обеспечивают согласованность.
